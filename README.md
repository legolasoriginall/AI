# دستیار دیجیتال (AI)

یک دستیار شخصی فارسی‌زبان که هم **آفلاین** (Ollama) و هم **آنلاین** (Gemini یا هر API سازگار با OpenAI) کار می‌کند؛ می‌تواند فایل بسازد، دستور اجرا کند و اطلاعات را در حافظهٔ محلی نگه دارد.

دو رابط دارد: یک CLI که مستقیم در ترمینال لینوکس چت می‌کند و دیگری یک رابط وب فارسی و راست‌به‌چپ. کل تاریخچهٔ گفتگوها در SQLite روی همان دستگاه ذخیره می‌شود.

## دموی آنلاین

نسخهٔ استاتیک رابط، با یک دموی تعاملی، روی GitHub Pages میزبانی می‌شود:
<https://legolasoriginall.github.io/AI/>

در آن صفحه، ساخت فایل، اجرای دستور و حافظه به‌صورت شبیه‌سازی‌شده در مرورگر اجرا می‌شوند (وضعیت در `localStorage` ذخیره می‌شود). پاسخ‌های واقعی مدل از دو راه ممکن است:

- **سرور واسط (پیشنهادی):** Worker آمادهٔ `worker/` را استقرار دهید و آدرسش را در بخش «اتصال مدل» بگذارید؛ کلید API سمت سرور می‌ماند. راهنما: `worker/README.md`.
- **اتصال مستقیم:** endpoint و مدل و کلید را در همان صفحه وارد کنید؛ کلید فقط در `localStorage` مرورگر خودتان می‌ماند و برای استفادهٔ شخصی روی دستگاه خودتان است، نه برای سایت عمومی.

ابزارهای واقعی فایل و شل فقط در اجرای Flask یا CLI در دسترس‌اند.

## امکانات

- **دو حالت اجرا:** آفلاین با Ollama، آنلاین با Gemini یا endpoint سازگار با OpenAI؛ انتخاب خودکار در حالت `auto`.
- **دو رابط:** `cli.py` برای ترمینال (بدون Flask و مرورگر) و رابط وب Flask.
- **ابزارها:** فهرست فایل‌ها، خواندن/نوشتن فایل و اجرای هر دستور bash (پایپ، ریدایرکت، sudo) — از داخل پوشهٔ `workspace`.
- **حافظه:** ثبت و بازیابی حقایق (`remember` / `recall`) و تزریق خودکار خاطرات مرتبط به دستور سیستمی.
- **گفتگو با استریم:** پاسخ‌ها تکه‌تکه می‌آیند؛ در CLI همان لحظه روی ترمینال و در وب به‌صورت SSE.
- **چند گفتگو:** ساخت، باز کردن و حذف نشست‌ها؛ در CLI با `/new` و در وب از نوار کنار.
- **مدیریت مدل:** پیدا کردن مدل‌های موجود، دانلود و نصب مدل پیشنهادی و انتخاب مدل فعال — در CLI با `/models` و `/use`، در وب از پنل «مدل‌ها»، یا با ابزارهای عامل `list_models`، `install_model` و `use_model`.
- **دستور سیستمی باز:** بدون محدودیت موضوعی؛ دستیار از هیچ درخواستی امتناع نمی‌کند و نتیجه را مستقیم می‌گوید.
- **کلیدها:** فقط از `.env` خوانده می‌شوند و در کد یا سایت عمومی نیستند.

## چت خط فرمان (لینوکس)

بدون Flask و مرورگر؛ فقط پایتون و ترمینال:

```bash
pip install -r requirements.txt
cp .env.example .env          # اختیاری: کلید یا آدرس مدل
python3 cli.py               # گفتگوی تعاملی با استریم
python3 cli.py -m "سلام"      # یک پیام و خروج
```

دستورهای داخل گفتگو:

| دستور | کار |
| --- | --- |
| `/help` | راهنما |
| `/new` | نشست تازه |
| `/models` | مدل‌های نصب‌شده و پیشنهادی |
| `/use qwen2.5:3b` | فعال‌کردن مدل نصب‌شده |
| `/status` | ارائه‌دهنده و مدل فعال |
| `/exit` | خروج |

`cli.py` خودش `.env` را می‌خواند (بدون وابستگی به `python-dotenv`)، ابزارها را در همان لحظه اجرا می‌کند و JSON خام ابزار را روی ترمینال چاپ نمی‌کند.

## اجرای وب (Flask)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # اختیاری: کلید یا آدرس مدل را بگذار
python server.py
```

سپس <http://127.0.0.1:3000> را باز کنید.

### حالت آفلاین (Ollama)

```bash
ollama serve
ollama pull llama3.2     # یا هر مدل دیگری
```

اگر Ollama روی همان دستگاه باشد، بدون هیچ کلیدی کار می‌کند؛ در تنظیمات هم می‌توانید مدل را انتخاب کنید.

### حالت آنلاین

در `.env` یکی از این‌ها را بگذارید:

```env
# هر API سازگار با OpenAI
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=...
ONLINE_MODEL=gpt-4o-mini

# یا Gemini / سرویس‌های رایگان
GEMINI_API_KEY=...
GROQ_API_KEY=...
OPENROUTER_API_KEY=...
```

نکته: کلیدها را در `.env` نگه دارید؛ این فایل در `.gitignore` است.

### Numes.ai

Numes هم با همان شکل Chat Completions کار می‌کند؛ فقط آدرس پایه و شناسهٔ مدل را عوض کنید:

```env
OPENAI_BASE_URL=https://api.numes.ai/api/v1
OPENAI_API_KEY=...
ONLINE_MODEL=openai/gpt-6-luna
```

کلید را فقط در `.env` (یا متغیر محیطی سرور) بگذارید. آن را در `docs/` یا هر سایت عمومی قرار ندهید: سایت GitHub Pages استاتیک و عمومی است و هر بازدیدکننده می‌تواند کلید را بخواند و از اعتبار شما خرج کند.

## مدیریت مدل‌ها

دستیار لازم نیست مدلش را از قبل بداند: فهرست مدل‌های نصب‌شده را می‌خواند، برای مدل‌های پیشنهادی دانلود را شروع می‌کند و مدل نصب‌شده را فعال می‌کند.

در CLI همین کارها با `/models` و `/use NAME` انجام می‌شود. در رابط وب، دکمهٔ **⬇** در نوار بالا پنل «مدل‌ها» را باز می‌کند و همین کارها را با پیشرفت زنده انجام می‌دهد. عامل هم می‌تواند خودش این ابزارها را صدا بزند: `list_models`، `install_model` و `use_model`.

| مسیر | کار |
| --- | --- |
| `GET /api/models` | مدل‌های نصب‌شده + فهرست پیشنهادی + مدل فعال |
| `POST /api/models/pull` | نصب مدل با `ollama pull` و استریم پیشرفت (SSE) |
| `POST /api/models/use` | فعال‌کردن یک مدل نصب‌شده (فقط نام‌های مجاز) |

### انتخاب خودکار بهترین مدل رایگان

حالت `auto` بدون تنظیم دستی، اول رایگان‌ترین گزینه‌ها را امتحان می‌کند:

1. **Ollama محلی** — بهترین مدل نصب‌شده به‌صورت خودکار انتخاب می‌شود: بزرگ‌ترین مدلی که با رم دستگاه (۶۰٪ آن) جا شود، با اولویت `qwen` و `llama`. اگر مدل ذخیره‌شده حذف شده باشد، به بهترین مدل موجود برمی‌گردد. هیچ کلیدی لازم نیست.
2. **Gemini** — اگر `GEMINI_API_KEY` در `.env` باشد.
3. **Groq** — اگر `GROQ_API_KEY` باشد (سهمیهٔ رایگان، مدل `llama-3.3-70b-versatile`).
4. **OpenRouter free** — اگر `OPENROUTER_API_KEY` باشد (مدل `meta-llama/llama-3.3-70b-instruct:free`).
5. در آخر `OPENAI_*` پولی و fallback عمومی (که به‌صورت پیش‌فرض خاموش است).

| سرویس | متغیر `.env` | مدل پیش‌فرض |
| --- | --- | --- |
| Ollama | — | خودکار از مدل‌های نصب‌شده |
| Gemini | `GEMINI_API_KEY` | `gemini-2.0-flash` |
| Groq | `GROQ_API_KEY` | `llama-3.3-70b-versatile` |
| OpenRouter | `OPENROUTER_API_KEY` | `meta-llama/llama-3.3-70b-instruct:free` |

هر سرویسی که کلیدش باشد خودکار وارد زنجیره می‌شود و اگر خطا بدهد، نفر بعدی امتحان می‌شود. برای دیدن زنجیرهٔ فعال، فیلدهای `best_local_model` و `free_providers` را در پاسخ `GET /api/status` ببینید.

### فهرست پیشنهادی

`llama3.2:1b` · `llama3.2:3b` · `qwen2.5:3b` · `gemma2:2b` · `qwen2.5:7b` · `llama3.1:8b`

فهرست در `providers.MODEL_CATALOG` و `docs/models.js` نگه داشته می‌شود؛ نام مدل پیش از نصب اعتبارسنجی می‌شود و فقط نام‌های همین فهرست با ابزار عامل قابل نصب‌اند.

## ساختار پروژه

| فایل | نقش |
| --- | --- |
| `cli.py` | چت خط فرمان با استریم و ابزارها، بدون Flask |
| `server.py` | Flask: صفحهٔ وب، استریم چت (SSE)، نشست‌ها، تنظیمات و فضای کاری |
| `providers.py` | روتر مدل‌ها: Ollama، Gemini، Groq/OpenRouter free، OpenAI-compatible و استریم |
| `agent.py` | حلقهٔ عامل: پارس کنش JSON، اجرای ابزار، پاسخ نهایی |
| `tools.py` | ابزارهای فایل/شل/حافظه؛ دستور bash بدون allowlist و فیلتر |
| `store.py` | SQLite برای نشست‌ها، پیام‌ها و حقایق + تنظیمات و دستور سیستمی |
| `web/` | رابط چت فارسی (HTML/CSS/JS بدون وابستگی) |
| `docs/` | سایت استاتیک GitHub Pages: صفحهٔ معرفی + دموی مرورگری + مدیر مدل |
| `worker/` | سرور واسط Cloudflare Worker: نگه‌داری کلید API سمت سرور |

## نحوهٔ کار عامل

مدل با یک دستور سیستمی راهنما می‌شود که هرگاه به ابزار نیاز داشت، فقط یک آبجکت JSON برگرداند:

```json
{"tool": "write_file", "args": {"path": "hello.py", "content": "print('سلام')"}}
```

سرور ابزار را اجرا می‌کند، نتیجه را به مدل برمی‌گرداند و این چرخه تا رسیدن به پاسخ نهایی (یا سقف `max_steps`) ادامه دارد. در CLI همین حلقه با استریم اجرا می‌شود و JSON ابزار به‌جای چاپ‌شدن، فقط به‌عنوان «⚙ ابزار» نمایش داده می‌شود.

## پشتیبانی لینوکس

این پروژه فقط برای لینوکس و خط فرمان (`bash`) مستند و آزمایش شده است. برای نصب، systemd، تونل HTTPS و عیب‌یابی، [راهنمای خط فرمان لینوکس](docs/linux-cli.html) را ببینید.

## محدودیت‌ها

- کیفیت پاسخ به مدل انتخابی وابسته است؛ مدل‌های کوچک محلی ممکن است در تولید JSON درست ضعیف باشند.
- `run_command` عمداً بدون allowlist است و با bash اجرا می‌شود؛ هر دستوری که بدهید اجرا می‌شود. این ابزار برای دستگاه شخصی است، نه استقرار عمومی.
- ابزارهای فایل مسیرها را به `workspace` محدود می‌کنند تا Path Traversal و symlink نتوانند از پوشه بیرون بزنند.
- `allow_public_fallback` در تنظیمات به‌صورت پیش‌فرض خاموش است، چون داده را به یک سرویس عمومی می‌فرستد.
