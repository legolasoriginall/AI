از صفر تا اجرا و آزمایش، بدون رابط گرافیکی: Ollama، نسخهٔ کامل Flask، سرور واسط Cloudflare Worker، تونل HTTPS، Docker و عیب‌یابی. بخش Flask این راهنما در یک محیط تازه واقعاً اجرا و تأیید شده است.

این راهنما همان سه مسیر سایت (آفلاین با Ollama، سرور واسط Worker، نسخهٔ کامل Flask) را برای محیط لینوکسی و بدون هیچ رابط گرافیکی، از صفر تا اجرا و آزمایش، توضیح می‌دهد. همهٔ دستورها در bash اجرا می‌شوند و روی اوبونتو/دبیان، فدورا، آرچ و توزیع‌های مبتنی بر آنها کار می‌کنند؛ تفاوت‌ها جداگانه گفته شده است.

مسیر پیشنهادی برای شروع: بخش ۲ (Flask) + بخش ۳ (Ollama). با این دو، هم مدل آفلاین داری و هم رابط کامل با ابزار فایل و دستور. اگر فقط می‌خواهی دموی سایت با مدل واقعی کار کند، بخش ۴ (Worker) را برو.

۲ · مسیر آفلاین: نصب Ollama روی لینوکس

مدل روی همین دستگاه اجرا می‌شود: بدون کلید API، بدون هزینه، بدون ارسال داده به بیرون.

نصب

نصب‌کنندهٔ رسمی:

curl -fsSL https://ollama.com/install.sh | sh
ollama --version

اگر sudo نداری یا نصب با اسکریپت را نمی‌خواهی، بستهٔ آماده را دستی بگیر (نسخه را از ollama.com/download/linux بردار):

mkdir -p ~/.local/ollama && cd ~/.local/ollama
curl -fL -o ollama.tgz "https://ollama.com/download/ollama-linux-amd64.tgz"   # aarch64: ollama-linux-arm64.tgz
tar -xzf ollama.tgz
export PATH="$HOME/.local/ollama/bin:$PATH"
ollama --version

برای دائمی‌شدن PATH، این خط را به ~/.bashrc اضافه کن:

echo 'export PATH="$HOME/.local/ollama/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

اجرای سرویس

روی سیستمی که systemd دارد، نصب‌کننده خودش سرویس می‌سازد:

sudo systemctl enable --now ollama
systemctl status ollama --no-pager

بدون systemd (کانتینر، WSL، سرور اشتراکی) در یک ترمینال جدا:

ollama serve
# یا در پس‌زمینه:
nohup ollama serve > ~/ollama.log 2>&1 &
echo $! > ~/ollama.pid

آزمایش سرویس

curl -s http://127.0.0.1:11434/api/tags
# {"models":[]}  ← خالی است چون هنوز مدلی نگرفته‌ایم

گرفتن مدل

ollama pull llama3.2:3b

مدل‌های پیشنهادی پروژه:

مدل حجم تقریبی مناسب برای
llama3.2:1b ~۱.۳ گیگابایت سبک‌ترین، سیستم کم‌رم
llama3.2:3b ~۲ گیگابایت تعادل سرعت و کیفیت
qwen2.5:3b ~۱.۹ گیگابایت فارسی بهتر، همان حجم
gemma2:2b ~۱.۶ گیگابایت پاسخ‌های کوتاه و سریع

llama3.1:8b ~۴.۹ گیگابایت کیفیت بالا، انگلیسی قوی‌تر

استفادهٔ مستقیم در ترمینال

ollama run llama3.2:3b
# >>> سلام، خودت را معرفی کن
# خروج: /bye

و تست API بدون رابط:

curl -s http://127.0.0.1:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"model":"llama3.2:3b","stream":false,"messages":[{"role":"user","content":"سلام"}]}' \
  | python3 -m json.tool

Ollama به‌طور پیش‌فرض فقط روی 127.0.0.1 گوش می‌دهد. اگر سرور از راه دور است و می‌خواهی Flask روی همان ماشین از آن استفاده کند، همین کافی است. باز کردن پورت روی اینترنت را در بخش ۷ ببین.

۳ · نسخهٔ کامل Flask (رابط وب + ابزار واقعی)

این نسخه چت واقعی، ابزار ساخت/خواندن فایل، اجرای دستور داخل workspace/، حافظهٔ SQLite و چند گفتگو دارد.

نصب در محیط مجازی

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt

هر بار که ترمینال تازه باز می‌کنی، دوباره source .venv/bin/activate لازم است.

تنظیمات

cp .env.example .env

.env را با یک ویرایشگر ترمینالی باز کن (nano .env یا vim .env):

# آفلاین — به Ollama روی همین دستگاه وصل می‌شود
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2:3b

# آنلاین (اختیاری) — هر API سازگار با OpenAI
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=
ONLINE_MODEL=gpt-4o-mini

# یا Gemini
GEMINI_API_KEY=

PORT=3000

.env در .gitignore است؛ کلید را هیچ‌جای دیگری (کد، docs/، چت، گیت) نگذار.

⚠️ نکتهٔ مهمی که در آزمایش عملی پیدا شد: python server.py خودش .env را نمی‌خواند. Flask فقط تذکر می‌دهد که فایل .env هست و python-dotenv نصب نیست؛ تنها Docker با env_file این فایل را به برنامه می‌رساند. برای اجرای مستقیم باید متغیرها را در همان شل export کنی:

set -a; . ./.env; set +a

بدون این خط، برنامه با مقدارهای پیش‌فرض بالا می‌آید و مثلاً OLLAMA_MODEL یا ONLINE_MODEL را از .env نمی‌بیند.

حالت auto خودش انتخاب می‌کند: اگر Ollama در دسترس باشد آفلاین، وگرنه آنلاین. برای اجبار به یکی، ارائه‌دهنده را در /api/settings یا از رابط وب → تنظیمات عوض کن.

اجرا

set -a; . ./.env; set +a      # .env را به محیط شل export کن
python server.py
# * Running on all addresses (0.0.0.0)
# * Running on http://127.0.0.1:3000

سپس در مرورگر همان دستگاه http://127.0.0.1:3000 را باز کن. اگر سرور بی‌نمایش است، از دستگاه خودت تونل بزن:

ssh -L 3000:127.0.0.1:3000 user@server
# بعد در مرورگر LOCAL: http://127.0.0.1:3000

اجرا در پس‌زمینه (بدون systemd)

nohup python server.py > ~/assistant.log 2>&1 &
echo $! > ~/assistant.pid
tail -f ~/assistant.log       # دیدن لاگ
kill "$(cat ~/assistant.pid)" # توقف

اجرای دائمی با systemd

sudo tee /etc/systemd/system/assistant.service >/dev/null <<'EOF'
[Unit]
Description=Digital Assistant (Flask)
After=network.target ollama.service

[Service]
Type=simple
User=USER
WorkingDirectory=/home/USER/AI
EnvironmentFile=/home/USER/AI/.env
Environment=PATH=/home/USER/AI/.venv/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/home/USER/AI/.venv/bin/python server.py
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

USER را با نام کاربری خودت عوض کن، سپس:

sudo systemctl daemon-reload
sudo systemctl enable --now assistant
systemctl status assistant --no-pager
journalctl -u assistant -f

آزمایش با curl

# سلامت
curl -s http://127.0.0.1:3000/api/health
# {"ok":true}

# وضعیت ارائه‌دهنده و مدل فعال
curl -s http://127.0.0.1:3000/api/status | python3 -m json.tool

# مدل‌های نصب‌شده + فهرست پیشنهادی
curl -s http://127.0.0.1:3000/api/models | python3 -m json.tool

# چت استریمی (SSE) — -N بافر curl را خاموش می‌کند
curl -N -X POST http://127.0.0.1:3000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"سلام، خودت را در یک جمله معرفی کن"}'

خروجی چت چند خط data: {...} است و با data: {"type": "end", ...} تمام می‌شود.

خروجی واقعی همین دستورها در یک محیط تازه (Python 3.12، بدون Ollama):

دستور نتیجهٔ دیده‌شده
GET /api/health {"ok":true}
GET /api/status 200 با provider:"auto"، ollama_ready:false و مدل‌های خوانده‌شده از .env
GET /api/models 200 با catalog پر و installed:[] — بدون Ollama هم خطا نمی‌دهد
POST /api/chat استریم SSE با error روشن («هیچ مدلی در دسترس نیست…») و سپس end — بدون کرش

مدیریت مدل از ترمینال

# نصب مدل (استریم پیشرفت)
curl -N -X POST http://127.0.0.1:3000/api/models/pull \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen2.5:3b"}'

# فعال‌کردن مدل نصب‌شده
curl -s -X POST http://127.0.0.1:3000/api/models/use \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen2.5:3b"}'

فقط نام‌های فهرست پیشنهادی (providers.MODEL_CATALOG) از این مسیر قابل نصب‌اند.

آزمایش‌های پروژه (اختیاری)

pip install -r requirements-dev.txt
pytest -q

۴ · مسیر سرور واسط: Cloudflare Worker

برای اینکه دموی استاتیک سایت با مدل واقعی کار کند و کلید هرگز به مرورگر نرسد. در محیط CLI دو حالت دارد: تعاملی (مرورگر همان دستگاه) یا بدون مرورگر با توکن API.

پیش‌نیاز

node --version      # 18 یا بالاتر؛ ترجیحاً 20
npx wrangler --version

اگر Node نیست، با nvm بدون root نصب کن:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install --lts

ورود به Cloudflare

حالت تعاملی (دستگاه با مرورگر):

npx wrangler login
npx wrangler whoami

حالت بدون مرورگر / سرور (پیشنهادی برای CLI): در داشبورد Cloudflare → My Profile → API Tokens، یک توکن با دسترسی Edit Cloudflare Workers بساز و فقط در همان نشست شل export کن:

export CLOUDFLARE_API_TOKEN='...'
export CLOUDFLARE_ACCOUNT_ID='...'      # از صفحهٔ Workers یا خروجی whoami
npx wrangler whoami

توکن را در فایل، ~/.bash_history یا گیت نگذار؛ برای نشست‌های بعد دوباره export کن یا از یک مدیر رمز استفاده کن.

تنظیم دامنهٔ مجاز

worker/wrangler.toml را باز کن و ALLOWED_ORIGINS را با دامنهٔ سایت خودت هماهنگ کن:

ALLOWED_ORIGINS = "https://legolasoriginall.github.io,http://localhost:3000,http://127.0.0.1:3000"
MODEL = "openai/gpt-6-luna"
MAX_TOKENS = "800"

گذاشتن کلید به‌صورت Secret

cd worker
npx wrangler secret put NUMES_API_KEY
# مقدار را همان‌جا وارد کن؛ در هیچ فایلی ذخیره نمی‌شود
cd ..

برای اجرای غیرتعاملی، بدون نمایش در تاریخچهٔ شل:

read -rs NUMES_API_KEY && printf '%s' "$NUMES_API_KEY" | (cd worker && npx wrangler secret put NUMES_API_KEY) ; unset NUMES_API_KEY

استقرار

bash scripts/deploy_worker.sh

اسکریپت ورود را بررسی می‌کند، Secret را در صورت نبودن می‌پرسد، deploy می‌زند، آدرس نهایی را چاپ می‌کند و همان‌جا smoke.mjs را روی نسخهٔ مستقرشده اجرا می‌کند. گزینه‌ها: --dry-run، --skip-smoke، --secret NAME.

دستی:

cd worker
npx wrangler deploy
cd ..

آزمایش

WORKER=https://ai-assistant-proxy.<account>.workers.dev

curl -s "$WORKER/health"
# {"ok":true,"configured":true,"model":"openai/gpt-6-luna"}

curl -s "$WORKER/api/models"
# {"models":[...],"default":"..."}

curl -N "$WORKER/api/chat" \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://legolasoriginall.github.io' \
  -d '{"messages":[{"role":"user","content":"سلام، یک جمله دربارهٔ پروکسی بگو"}]}'

تست محلی بدون کلید و بدون حساب

cd worker
npx wrangler dev --port 8787        # ترمینال اول
node smoke.mjs                       # ترمینال دوم، در همان پوشه
node test.mjs                        # ۳۳ بررسی آفلاین، بدون شبکه

وصل کردن به دموی سایت

در سایت → «دموی زنده» → «اتصال مدل»: آدرس Worker را در «آدرس سرور واسط» بگذار، بقیهٔ فیلدها (endpoint/مدل/کلید) خالی. سپس «تست اتصال» بزن؛ سه حالت را نشان می‌دهد: آماده، کلید سمت سرور تنظیم نشده، یا مبدأ رد شده.

۵ · تونل HTTPS برای Ollama (استفاده از دموی Pages)

دموی سایت روی HTTPS است و مرورگر اجازهٔ تماس مستقیم با http://127.0.0.1:11434 را نمی‌دهد (mixed content + CORS). اسکریپت پروژه هر دو را حل می‌کند.

نصب cloudflared

# دبیان/اوبونتو
curl -fL -o cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
cloudflared --version

بدون root:

mkdir -p ~/.local/bin
curl -fL -o ~/.local/bin/cloudflared https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x ~/.local/bin/cloudflared

(روی aarch64 فایل cloudflared-linux-arm64 را بردار.)

اجرای تونل

bash scripts/ollama_tunnel.sh
# آدرس https://…trycloudflare.com چاپ می‌شود

گزینه‌ها: --port 11434، --origin https://my-site.example (قابل تکرار)، --dry-run، --help. با Ctrl+C هر دو فرآیندی که خودش ساخته بسته می‌شود.

سپس همان آدرس HTTPS را در سایت → «مدل‌ها» → «آدرس Ollama» بگذار و «جست‌وجوی دوباره» بزن.

نکته‌ها:

  • OLLAMA_ORIGINS فقط هنگام شروع ollama serve خوانده می‌شود؛ اگر Ollama از قبل در حال اجراست اول ببندش (sudo systemctl stop ollama یا kill "$(cat ~/ollama.pid)").
  • تونل trycloudflare عمومی و موقت است و تا وقتی اسکریپت باز است کار می‌کند؛ آدرسش را منتشر نکن.
  • Ollama هیچ احراز هویتی ندارد؛ هر کسی با آن آدرس می‌تواند مدل‌ها را صدا بزند.

۶ · مسیر Docker (بدون venv)

cp .env.example .env      # کلید/مدل را اینجا بگذار
docker compose up --build -d
docker compose logs -f
docker compose down

اگر Ollama روی میزبان اجرا می‌شود، در .env آدرس را به میزبان اشاره بده (OLLAMA_URL=http://host.docker.internal:11434) و روی لینوکس به سرویس extra_hosts نیاز داری؛ ساده‌ترین راه این است که Ollama را هم داخل Compose بیاوری یا Flask را بدون Docker اجرا کنی.

۷ · عیب‌یابی

نشانه علت راه‌حل
Address already in use پورت ۳۰۰۰ اشغال است ss -ltnp \| grep 3000 و PORT=3001 python server.py
ollama: command not found PATH export PATH="$HOME/.local/ollama/bin:$PATH"
connection refused روی 11434 سرویس بالا نیست ollama serve یا systemctl start ollama
model not found مدل دانلود نشده ollama pull llama3.2:3b
فارسی به‌هم‌ریخته در ترمینال لوکال ترمینال export LANG=fa_IR.UTF-8 یا از رابط وب استفاده کن
Worker: 403 origin_not_allowed دامنه در ALLOWED_ORIGINS نیست دامنه را اضافه و دوباره deploy کن
Worker: 500 server_not_configured Secret خوانده نشده npx wrangler secret put NUMES_API_KEY و deploy دوباره
Worker: 502 upstream_error کلید/مدل نامعتبر پیام message را ببین؛ کلید را در داشبورد بررسی کن
مرورگر: mixed content تماس HTTPS با http://127.0.0.1 از تونل بخش ۵ استفاده کن
مدل/کلید از .env خوانده نمی‌شود server.py خودش .env را لود نمی‌کند set -a; . ./.env; set +a پیش از اجرا، یا EnvironmentFile در یونیت systemd
pip install کند یا خطای شبکه آینه یا پروکسی pip install -i https://pypi.org/simple -r requirements.txt

۸ · امنیت و نگهداری

  • کلیدها فقط در .env (سرور Flask) یا Secret در wrangler؛ هرگز در docs/، کد، گیت یا چت.
  • نسخهٔ Flask ابزار اجرای دستور دارد و احراز هویت ندارد: روی اینترنت بازش نکن. برای دسترسی از راه دور از ssh -L استفاده کن.
  • پورت 11434 را روی اینترنت باز نکن؛ برای دمو از تونل موقت استفاده کن.
  • workspace/ را دوره‌ای خالی کن؛ ابزارها فقط داخل همین پوشه کار می‌کنند.
  • به‌روزرسانی: git pull، pip install -r requirements.txt، ollama pull <model>، و برای Worker دوباره bash scripts/deploy_worker.sh.
  • پشتیبان‌گیری: فایل SQLite و .env را کپی کن؛ بهتر است .env در پشتیبان رمزنگاری‌شده باشد.

۹ · چک‌لیست کوتاه

# آفلاین
ollama --version && ollama pull llama3.2:3b
curl -s http://127.0.0.1:11434/api/tags

# Flask
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && cp .env.example .env
python server.py
curl -s http://127.0.0.1:3000/api/health

# Worker (اختیاری)
npx wrangler whoami && bash scripts/deploy_worker.sh
curl -s https://<worker>/health

وقتی {"ok":true} گرفتی، همه‌چیز آماده است: رابط کامل روی http://127.0.0.1:3000، مدل آفلاین روی 11434، و در صورت نیاز سرور واسط روی workers.dev.
